# 审查规范

由[顶层规范](../../AGENTS.md)按任务路由，适用于代码审查和缺陷归因。

- 明确审查范围与基线，沿真实产品入口判断行为，并考虑已有约束。
- 已确认缺陷必须说明：预期行为、可达的触发条件、用户影响、代码位置和证据范围。
- 区分产品功能错误、诊断缺陷、设计限制与健壮性建议；不能仅因缺少防御逻辑而认定产品有错。
- 人工构造的失败只证明相应条件下的行为，必须说明这些条件在产品中是否可达。
- 核对历史后区分新增回归、已有问题和影响扩大的问题；说明归因依据，不把历史代码核对说成历史版本实测。
- 优先级依据实际影响、可达性与证据强度，不依据测试失败次数；低频的重大风险也不能忽略。
- 不追求发现数量。证据不足的候选明确标为待验证，不进入已确认缺陷清单。
- 建议采用与问题相称的最小修正，不借审查扩大架构改造。审查不默认授权修改实现。
- 可选改进不作为阻断项；复审聚焦未解决问题及变更影响，没有新需求或证据时不扩大验收范围。

| 等级 | 含义 |
| --- | --- |
| P0 | 需立即处理的严重事故或普遍不可用 |
| P1 | 当前支持场景中已证实的重大影响，需优先修复 |
| P2 | 影响明确的局部功能缺陷，按正常维护修复 |
| P3 | 轻微缺陷或影响受限的已确认边界 |

报告先列实际问题，再列待验证事项；说明验证限制。复现与验证遵循[测试规范](../testing/AGENTS.md)，发现误判时直接更正。
