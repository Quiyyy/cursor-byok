# 测试规范

由[顶层规范](../../AGENTS.md)按任务路由，适用于行为修改、复现与验收。

- 从产品需求定义输入、操作和预期结果，断言外部行为与必要约束，不复述实现。
- 确认的行为缺陷应有能区分修复前后的回归验证。
- 覆盖本次改动涉及的正常流程和必要边界，验证范围与实际风险相称。
- 并发与异常测试应对应可达场景，并明确人工控制条件；可重复失败不等于常见产品故障。
- 模拟测试、集成测试和真实环境测试分别报告，各自的结论不能超出覆盖范围。
- 测试数据、资源与用户环境隔离；测试负责释放或还原自己创建的资源和改动。
- 采用当前项目已有检查能力。通过后仅因新增改动、失败或具体未决问题重跑或扩大验证。
- 区分实现缺陷、环境问题和测试错误，不通过削弱有效断言掩盖失败。
- 纯文档改动检查事实、引用和规范一致性，不因此运行无关的应用测试。

当前命令与环境要求见[维护指南](../../MAINTAINING.md)和[CI](../../.github/workflows/ci.yml)。将失败报告为产品缺陷前，遵循[审查规范](../review/AGENTS.md)。
