# 测试与验收规范

这是由[顶层入口](../../AGENTS.md)路由的跨目录任务规范。适用于行为修改、回归用例和问题复现。判定一个失败是否构成产品缺陷时，同时使用[审查规范](../review/AGENTS.md)。

## 测什么

1. 用一句话写明用户入口、前置配置、操作和预期结果。覆盖修改涉及的协议分支和状态所有者，避免先写一个只对内部实现成立的断言。
2. 对确认的行为 bug，先构造有辨识力的回归：修复前失败，修复后通过。测试应断言输出、状态或资源结果，不复述实现顺序。
3. 测试公共边界最有价值：真实路由配模拟上游、持久化往返、实际 Worker、用户可用控件。单元测试用于定位和覆盖组合，不代替所有入口验收。
4. 新增参数层、重试或生命周期转换时，检查相邻行为：显式值与缺省值、成功与失败、取消与完成，以及是否影响下一次独立调用。按真实分支选取，不做无依据的笛卡尔积。
5. 并发用例先说明生产中相应事件如何发生，再使用屏障确定顺序。不要依靠随机 sleep 证明竞态；需要验证实际超时时间时说明计时依据。

## 按改动选择检查

命令从仓库根目录运行，除非另有注明。脚本以当前分支的 [package.json](../../apps/desktop/package.json)、[Cargo.toml](../../Cargo.toml) 和 [CI](../../.github/workflows/ci.yml) 为准。不要从其他分支复制不存在的命令。

| 改动 | 首轮验证 | 需要扩大验证的条件 |
| --- | --- | --- |
| 纯文档 | 相对链接、目录 / 文件存在、命令存在、规则一致性、`git diff --check` | 文档声称当前行为时，核对实现；不因此运行整套应用测试 |
| React / TypeScript | `npm --prefix apps/desktop run check`；已有相关测试或定向交互验证 | 跨页面状态、HTTP 边界、桌面布局变更时做相关页面 / 桌面验证 |
| Rust 局部行为 | 对应 crate / 集成测试的定向用例，`cargo fmt --all --check` | 公共类型、跨模块依赖或调用链变化时扩大到相关集成测试与工作区检查 |
| 原生入口与路由 | `node --test server/native-agent/*.test.mjs`；`node server/native-agent/build.mjs --check` | 改变安装、Host 所有权或原生交互时，按原生接入规范验收隔离安装 |
| API 转发 / 协议转换 | `cargo test -p cursor-server --test external_api`，相关协议测试 | 多协议公共规则变化时覆盖同协议、跨协议与账号路径中实际受影响的分支 |
| Tauri 生命周期 / 打包 | 对应桌面 Rust 检查；`npm --prefix apps/desktop run tauri:build -- --debug --no-bundle` | 涉及真实窗口、托盘、退出或更新时进行对应平台的隔离验证 |
| 账号插件 / SDK | 修改插件的 Deno 测试；涉及宿主凭据时运行下方 Rust 插件测试 | SDK 公共契约变化时覆盖各受影响插件，不调用真实账号代替夹具 |

公共 Rust 调用链、跨组件重构以及交付要求完整检查时运行：

```sh
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

插件宿主测试要求先将 `DENO_TEST_EXECUTABLE` 设置为本机 Deno 可执行文件路径：

```sh
cargo test -p cursor-server --lib plugin:: -- --include-ignored
```

各插件的 Deno 命令见 [MAINTAINING.md](../../MAINTAINING.md)。`ignored` 测试未执行时明确列出，不能把默认 `cargo test` 的成功描述为覆盖所有插件生命周期。

组件技能明确要求的检查仍需完成。检查通过后，只有新增改动、失败或未解决的具体疑点才扩大或重跑；不要反复跑全套测试替代对问题的判断。

## 隔离与清理

- 使用临时 SQLite、插件数据目录和本地 HTTP 夹具；优先显式 `in_directory` 等隔离构造器，不读取正式账号代替测试输入。
- 桌面与原生验证隔离 BYOK 数据、Cursor 安装 / 用户目录及桌面应用标识；环境设置限制在测试进程。具体步骤见 [MAINTAINING.md](../../MAINTAINING.md) 与 [原生接入规范](../../server/native-agent/AGENTS.md)。
- 验证证书、真实接管、账号续期或付费服务商调用时，先核对任务授权和环境边界，不把它们夹带进普通冒烟测试。
- 测试拥有自己启动的进程、端口、临时写入和全局变量，并负责释放或还原；不要按进程名批量终止用户应用。
- 故障注入可以模拟上游错误和连接中断；若绕过了正常路由、校验或锁，要保留该限制，不能用它直接断言产品可达性。
- 不为低影响可逆文案 / 样式修改堆砌测试，不引入仅为一次探针服务的生产抽象或长期依赖。

## 结论的范围

- 区分静态检查、单元测试、真实入口配模拟上游、实际桌面 / Cursor 和真实服务商验证。各自只能证明各自覆盖的行为。
- 构建成功不能证明 UI 正确；内部取消状态不能证明远端已停止；一次文件编辑不能证明全部原生工具和跨进程恢复正确。
- 报告具体命令及结果、跳过的测试和原因、平台及必要版本。测试数量可以辅助说明，不能代替入口和断言范围。
- 遇到失败，先区分代码回归、原有缺陷、环境问题和测试设计错误。不要只改断言让测试变绿，也不要把每个探针失败都升级为新功能需求。
