# 桌面与前端维护规范

适用于 `apps/desktop/`。共同约束见[顶层入口](../../AGENTS.md)。修改 `src-tauri/` 时继续读[宿主规范](src-tauri/AGENTS.md)；纯 Rust 宿主任务不需要加载无关的 UI 技能。

## 组件边界

```text
src/                    # React 管理界面
├── App.tsx             # 路由组合
├── features/           # 具体产品功能与界面
├── shell/              # 导航、布局与窗口界面
├── shared/             # API、状态和通用控件
├── i18n/               # 语言选择、词条与生成目录
├── styles/             # 主题与排版规范
└── demo/               # 演示数据与截图运行环境
src-tauri/              # 原生窗口与进程能力，不持有第二套业务 API
```

```text
用户动作 → 功能状态 / action → shared API → Rust control → 持久化
显示状态 ← 服务端响应 / 功能快照 ←───────────────────┘
瞬时界面状态 → 当前组件（焦点、开关面板、编辑草稿）
```

- 模型、账号、调用记录和持久设置属于业务状态；不要散落在展示组件里。拆状态模块必须追踪初始化、刷新、切页缓存、修改后的失效与错误恢复。
- 不因为分层目标而一次重写所有页面或增加通用状态框架。复用现有状态与组件模式，确认真实耦合后再拆分。
- 前端不能自行推断接管已成功；开关显示以服务端返回为准。检查加载、失败、处理中和部分启用状态，失败后恢复操作应真实可达。
- 全局能力不要依赖某个页面是否挂载。页面刷新不应意外触发接管安装或生命周期变更。

## HTTP 与界面约束

- 管理页面从 Rust 的 `/__byok-api__/` 加载，管理请求相对访问 `/__byok-api__/api`。不新增固定端口、第二来源或业务 IPC 镜像。
- 原生 IPC 仅承载窗口、托盘、终端、系统交互等桌面能力。前端和浏览器详情页共用 HTTP 边界。
- 保留公共页面布局、虚拟滚动、统一控件和主题 token；不要为局部样式重新建立页面容器或独立滚动体系。
- 控件的禁用、错误提示、键盘访问和恢复入口都属于用户行为；只验证 store 方法可调用不足以证明按钮可用。

## 验证与交付

- 遵循[测试规范](../../.agents/testing/AGENTS.md)。修改前端代码时运行当前分支已有前端检查；有状态测试脚本时运行受影响用例，不臆造未存在的命令。纯文档变更只做文档检查。
- 状态修改验证初始化、失败恢复和用户动作；布局修改验证最小窗口、页面滚动与固定区域；涉及宿主时做相关桌面构建和隔离交互检查。
- 本地化生成文件由扫描工具生成，避免手改。演示模式使用示例数据，不接入正式账号。
- 没有真实交互验证时，报告类型检查 / 构建或组件测试的范围，不能宣称“页面功能完全正常”。
