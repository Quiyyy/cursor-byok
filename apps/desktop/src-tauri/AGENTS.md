# 桌面宿主维护规范

适用于 `apps/desktop/src-tauri/`，继承[桌面规范](../AGENTS.md)。服务生命周期交叉修改同时读取 [Server 规范](../../../server/AGENTS.md)和[测试规范](../../../.agents/testing/AGENTS.md)。

## 所有权

```text
Tauri 进程              # 窗口、托盘、显式退出与更新入口
  → Rust App            # HTTP 服务及服务资源生命周期
    → CursorHarness     # 接管设置、代理与原生安装恢复
  ← 服务结果 / 错误     # 宿主决定何时完成进程退出
```

- 宿主负责创建与等待服务，不复制 Provider、账号、配置持久化等服务业务。
- 区分关闭窗口、后台托盘运行、显式退出和更新重启。修改其中一条路径时，检查其他入口是否共用状态与结束回调。
- 修改生命周期时，先画出受影响的启动、接管变更、停止和资源释放顺序，说明任务由谁持有、谁能取消、谁确认完成。不要用“有超时”代替所有权分析。
- 超时要指明限制哪项操作，超时后任务是否仍运行、资源由谁清理。不要随意叠加第二个更短期限，也不要无依据地改成无限等待。
- 多次退出请求和正在执行的管理请求按真实入口审查；人工门闩能证明调度顺序，但不能单凭它宣布常见退出故障。
- 组件错误要保留可诊断信息。任何“已退出 / 已清理”的状态都应有相应完成条件，而不是只表示发出了请求。

## 系统边界与验证

- 保留 Rust 提供页面资源和管理 API 的同源模式，复用 Tauri 资源解析器，不额外复制前端资源或新增业务 IPC。
- 使用隔离应用标识和数据目录进行桌面验证，具体命令见 [MAINTAINING.md](../../../MAINTAINING.md)。临时配置、签名覆盖和安装包不进入提交。
- 一般桌面修复不授权安装 CA、修改系统信任、重启用户正在使用的 Cursor 或调用正式账号。
- 生命周期测试覆盖本次变更涉及的正常启动 / 退出和可达的中断边界。只使用模拟 server future 时，明确它没有验证真实安装器与托盘。
- 修改宿主代码时完成对应平台 Rust 检查和桌面构建；Linux / Windows / macOS 的构建或 UI 结论分别报告，不相互替代。纯文档变更按测试规范检查文档。
- 修改版本、更新器、签名或发布资产时加载[发布技能](../../../.agents/skills/release/SKILL.md)。普通提交不自动扩大为发布任务。
