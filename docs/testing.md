# 自动化验收

本文记录当前测试入口及证据范围，不定义新的产品规范。普通 CI 无需 Cursor 安装、正式账号或付费模型；依赖安装完成后，新增验收用例只使用本地进程与回环网络。

## 能力与测试对应

| 能力 | 测试入口 | 证明范围 |
| --- | --- | --- |
| 原生网关鉴权、接管开关、同名配置隔离 | `server/src/local_app/native_agent/tests.rs` | 生产路由、真实 Store 和 HTTP 上游；原生密钥与 External API 独立，实际请求进入选中的连接 |
| 原生参数、身份及调用记录 | 同上 | 直接转发与协议转换均保留显式参数、原生会话和运行身份；配置模板使用会话 ID，内部头不透传 |
| 上下文容量、重置、协议参数转换 | 上述原生用例及 `server/tests/external_api.rs` | 复用已有容量和协议矩阵，不在每个入口重复整套组合 |
| 直接 API 取消 | `disconnecting_native_stream_closes_upstream_and_allows_the_next_run` | 真实 HTTP 客户端断流后，上游连接关闭、调用记录终结；下一运行正常。覆盖直接和转换两条路径 |
| 插件取消 | `plugin::registry::tests::cancellation_reaches_the_worker_without_cancelling_the_next_invocation` | 丢弃网关响应后，真实 Deno worker 收到取消；下一调用独立，记录不残留 running |
| 插件网络取消 | `plugin::worker::network::tests::cancelling_plugin_network_closes_a_connection_waiting_for_tls` | 等待 TLS 响应时取消实际 socket；不安装测试 CA、不放宽 HTTPS 校验。流式响应由直接 API 用例覆盖，不能据此宣称插件所有网络阶段均已覆盖 |
| 鉴权重试 | `plugin::registry::tests::worker_auth_retry_uses_persisted_credentials_and_never_replays_partial_output` | 真实 Deno worker 首次拒绝凭据、持久化刷新、重试成功；已经输出后不重试；各次调用记录独立 |
| 重试记录详情和并发凭据刷新 | 既有 `plugin::worker::network::tests`、`plugin::registry::tests` | 复用详细/普通日志、并发刷新及取消后凭据落盘回归 |
| 设置刷新、默认模型、上下文交互 | `apps/desktop/tests/ui/settings.spec.mjs` | 生产前端与真实 Rust 管理服务；实际点击、保存、重新加载后核对界面及持久化数据 |
| 功能失败隔离 | `apps/desktop/tests/state.test.mjs` | 复用已有状态测试，页面测试只补交互接线与真实服务闭环 |
| 子任务、搜索、Steer、新对话入口 | `server/native-agent/*.test.mjs` | 接入模块与合成私有边界的契约；不等于真实 Cursor 执行器验收 |

网关测试只设置隔离数据库中的接管状态，以测试鉴权和模型路由，不执行系统接管。页面测试只对初始目录 GET 注入 503；恢复后的读取、保存及持久化均使用真实服务。插件重试使用本地测试插件返回认证错误，不代表真实服务商授权测试。

## 运行

现有 Rust、Node、Deno、状态及构建检查见[维护指南](../MAINTAINING.md#检查)。插件 worker 用例沿用 `DENO_TEST_EXECUTABLE` 和 `--include-ignored` 专项步骤；未执行该步骤不能计为通过。

页面测试在仓库根目录准备前端与服务：

```sh
npm --prefix apps/desktop ci
npm --prefix apps/desktop run check
cargo build --locked --package cursor-server --bin cursor-server
```

再进入 `apps/desktop`：

```sh
npx playwright install chromium
npm run test:ui
```

测试读取仓库 `target/debug/cursor-server`（Windows 为 `.exe`）；设置 `CARGO_TARGET_DIR` 时使用其绝对路径。每个页面用例启动独立服务、临时数据目录和随机端口，页面与 API 同源；结束后关闭进程并删除临时数据。

[CI](../.github/workflows/ci.yml) 的 Linux Rust job 构建服务，Frontend job 复用该产物与自己的生产前端构建执行 Chromium 测试。失败时上传 `target/ui-tests/` 中的报告、截图、trace 和服务日志。用例不自动重试；时序测试等待事件并设置超时。

## 剩余验收边界

下表列出当前自动化尚未覆盖的产品链路，不表示这些内容永久无法自动化。涉及对应变更、首次支持某种环境或收到相关问题反馈时，由人工或具备桌面操作能力的 agent 完成受影响项；能够稳定复现的边界优先补入现有自动化测试。

目前的主要限制：

- Node 原生接入测试使用合成的私有边界，未启动真实 Cursor。网关测试设置隔离数据库中的接管状态，不验证实际安装、模型菜单和 Host 的动作投递。
- 页面测试使用 Chromium 和独立 Rust 服务，仅覆盖设置页目录恢复、默认模型及上下文保存。它不是 Tauri WebView、桌面宿主或整套管理界面的验收。
- 插件测试运行真实 Deno，但使用测试插件或模拟服务商响应；网络取消专项只观察等待 TLS 响应时的连接关闭。不能推广为所有真实插件的流式阶段、认证后端和网络环境均通过。
- CI 的平台编译与插件测试不覆盖对应系统上的证书信任、代理、安装恢复和桌面交互。历史验收记录也不自动证明新构建、新 Cursor/Harness 或新账号组合通过。

### 人工或 agent 的端到端验收清单

“真实客户端＋夹具”指使用实际 BYOK 构建和 Cursor，由本地确定性服务控制模型输出；Cursor 的工具、会话、审批和执行循环仍使用原生实现。“真实服务”指另外使用对应账号和服务商，验证外部兼容性。两类结果分别记录。

| 编号与范围 | 何时补验 | 操作与通过标准 | 所需环境 |
| --- | --- | --- | --- |
| E01 接管与 Harness | 接入补丁、Cursor/Harness、安装位置或平台变化 | 开启接管并重启目标 Cursor，核对实际加载的 Harness 路径/版本，发送请求确认进入当前 BYOK。分别记录默认热更新环境与固定内置 Harness 的结果；不能只固定旧 Harness 测通后宣称默认环境通过 | 真实客户端＋夹具 |
| E02 菜单、模型选择与默认值 | 目录编码、模型元数据、创建入口变化 | 从菜单分别选择同名不同连接的模型，核对实际地址和模型 ID；新窗口及新对话应用默认值，恢复旧对话和手动选择不被覆盖。切到官方模型或 Auto 时保持原生路径；不可用默认值明确失败 | 真实客户端＋夹具；官方实际调用另用真实服务 |
| E03 上下文、思考强度与摘要 | 容量、档位、元数据刷新或历史传递变化 | 在同一会话调小、调大并重置容量，核对下一轮预算与指示器；切换实际声明的思考档位并检查上游参数，有关闭选项时验证关闭。长任务触发原生摘要后仍可继续，不能因单位错误反复提前摘要 | 真实客户端＋夹具；服务商参数接受情况用真实服务 |
| E04 文件、终端、审批与 MCP | Host 状态传递、工具协议、模式或权限接入变化 | 完成读取、修改、运行测试、复读文件的闭环；对无害命令分别批准和拒绝，核对副作用；调用一个结果确定的本地 MCP 工具。审批、工具卡片、编辑接受/拒绝和 Todo 更新符合原生行为 | 真实客户端＋夹具、本地测试仓库及 MCP |
| E05 Subagent | Task 工厂、配置身份、父子会话或相关模型协议变化 | 由父任务发起子任务，让子任务读取独立文件中的随机标记并回传；检查子任务实际使用的模型连接及独立运行身份，父任务收到有效结果。涉及并行或取消变更时补测多子任务和父子取消，按目标 Cursor 的原生语义判断 | 真实客户端＋夹具 |
| E06 WebSearch 与 WebFetch | 搜索接入、响应转换、引用展示或认证路径变化 | 官方搜索成功时得到实际结果且不重复调用服务商；受控失败后验证备用路径。核对答案、来源卡片中的页面标题与可访问链接，不能以占位文本判成功；WebFetch 读取含随机标记的网页。拒绝审批、取消和原生隐私限制不被绕过 | 真实客户端＋夹具验证展示和分支；官方及服务商搜索各用真实服务 |
| E07 Stop 与再次发送 | 控制桥、流传输、插件取消或运行清理变化 | 分别在等待响应、流式输出和无害工具任务期间点击 Stop，观察对应取消结果及上游连接；再发送新消息，确认没有旧尾段、旧工具结果或取消信号混入。已经完成的文件修改不要求自动回滚 | 真实客户端＋夹具；直接 API 和账号插件分别覆盖 |
| E08 Steer、Queue 与 Interrupt | 动作接收器、注入记录、步骤边界或 Cursor 控制入口变化 | 多步骤任务中发送引导，检查下一步骤消费一次且保持同一运行；不能等整轮结束才生效。目标版本提供 Queue/Interrupt 时分别验证排队到后续运行和取消后创建新运行，检查投递状态及重复消费 | 真实客户端＋夹具 |
| E09 历史、恢复与会话隔离 | 会话身份、历史投影、checkpoint 或模型切换路径变化 | 多轮工具往返后换模、重开 Cursor 并继续；核对历史、选择与参数的恢复。两个会话使用不同标记并行运行，不串请求、结果或停止动作；普通追加轮次保持历史前缀，原生摘要或换模导致的变化单独辨认 | 真实客户端＋夹具 |
| E10 真实模型与账号 | API/插件适配、授权流程、目录解析变化或上游问题反馈 | 对受影响通道完成实际授权、目录同步、一次普通回复和工具往返；核对模型 ID、用量及错误。涉及续期时使用可控过期场景；额度、撤销授权及参数不支持的错误应准确呈现，夹具成功不能代替真实服务可用性 | 真实客户端＋真实服务 |
| E11 插件流式网络 | worker 网络、SDK 流读取、代理或取消路径变化 | 通过真实账号插件进入正在流式读取的请求，停止后观察服务端连接结束，并继续下一次调用；涉及断流/空闲超时时补相应场景。当前 TLS 等待测试不能替代这个闭环 | 真实插件＋可控 HTTPS 上游；真实代理/服务兼容性另验 |
| E12 桌面、安装与恢复 | Tauri 宿主、接管生命周期、证书、代理、更新或打包变化 | 使用实际桌面构建完成证书准备、开启/关闭接管、关闭窗口留后台、正常退出与重开；核对文件哈希、代理设置及状态。涉及异常退出或 Cursor 更新时验证恢复，不用旧备份覆盖新版本文件；发布更新变更另验对应安装/更新入口 | 目标 OS 的隔离安装与用户目录 |
| E13 管理界面的其余交互 | 未被现有三项页面用例覆盖的界面变更 | 对受影响的新增/编辑/复制/删除模型、账号操作、调用详情、筛选、清理或主题/语言执行真实操作，核对持久化、错误恢复和可用性。浏览器可稳定验证的部分优先新增 UI 用例；WebView、托盘及系统窗口差异使用桌面构建 | 浏览器或实际桌面，按所改能力选择 |
| E14 Commit、TAB 与图像 | 对应辅助接口、路由配置或原生入口变化 | 在测试仓库从 SCM 生成提交信息，核对选中模型与实际暂存差异；分别验证 TAB 直连及有兼容服务时的自定义路由。对声明支持的模型验证图像输入/生成与文件结果，不支持的连接明确报错 | 真实客户端＋对应夹具或真实服务 |

E05/E06 对应 [Issue #8](https://github.com/Quiyyy/cursor-byok/issues/8)，其中搜索来源的可见性必须从 Cursor 界面检查；E07/E08 对应 [Issue #11](https://github.com/Quiyyy/cursor-byok/issues/11)，按钮停止、连接关闭与步骤引导分别取证。不能仅用工具调用开始、返回 agent ID、网关 HTTP 200 或最终一段回答判定这些项目通过。

Remote SSH、云端工作区、后台 Agent、在途子任务跨进程恢复，以及未列出的平台、模式或 MCP 组合，不从本地用例推导支持或通过。若任务要求支持这些场景，先明确预期行为和环境，再建立专项用例；不把全部探索项默认加入每个 PR 的验收要求。

### 执行、证据与复用

1. 根据本次变更选择表中编号，并写明未选择项沿用哪份既有记录及其适用条件。普通配置、协议和管理页面变更若已由相关自动化完整覆盖，不机械重复人工清单；出现新的真实环境故障证据时再补验。
2. 使用独立安装、BYOK 数据目录、Cursor 用户目录及测试仓库。记录 BYOK 提交/构建、OS、Cursor 版本、实际 Harness 路径/版本和模型通道；临时固定 Harness、修改配置或限制网络必须作为验收条件记录，并在结束后还原。
3. 从对应用户入口操作，关联界面结果、脱敏请求/取消时序、真实文件或工具结果及必要的会话身份。协议夹具不替换原生执行器；真实模型是否遵循指令与指令是否被正确送达分别判断。
4. 每项标为通过、失败、阻塞、未验收或不适用，并附证据位置和原因。缺账号、额度、平台或运行入口时不能计为通过；原生行为不明确时先核对同版本基线，避免把推测写成缺陷。
5. 关闭测试进程并核验安装、代理和临时配置已恢复。证据仅保留脱敏摘要；不提交凭据、完整用户数据库、Cursor 安装备份或私有会话内容。
