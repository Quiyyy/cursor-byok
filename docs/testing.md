# 自动化验收

本文记录当前测试入口及证据范围，不定义新的产品规范。普通 CI 无需 Cursor 安装、正式账号或付费模型；依赖安装完成后，新增验收用例只使用本地进程与回环网络。

## 能力与测试对应

| 能力 | 测试入口 | 证明范围 |
| --- | --- | --- |
| 原生网关鉴权、接管开关、同名配置隔离 | `server/src/local_app/native_agent/tests.rs` | 生产路由、真实 Store 和 HTTP 上游；原生密钥与 External API 独立，实际请求进入选中的连接 |
| 原生参数、身份及调用记录 | 同上 | 直接转发与协议转换均保留显式参数、原生会话和运行身份；配置模板使用会话 ID，内部头不透传 |
| 上下文容量、重置、协议参数转换 | 上述原生用例及 `server/tests/external_api.rs` | 复用已有容量和协议矩阵，不在每个入口重复整套组合 |
| 直接 API 取消 | `disconnecting_native_stream_closes_upstream_and_allows_the_next_run` | 真实 HTTP 客户端断流后，上游连接关闭、调用记录终结；下一运行正常。覆盖直接和转换两条路径 |
| 插件取消 | `plugin::registry::tests::cancellation_reaches_the_worker_without_cancelling_the_next_invocation` | 丢弃网关响应后，真实 Deno worker 收到取消；下一调用独立，记录不残留 running |
| 插件流式网络及确定性取消 | `plugin::registry::tests::streaming` | 真实 Deno worker 经 SDK 读取本地 HTTPS 流，收到首段后分别显式取消、仅丢弃接收器；后者的取消令牌始终未触发。验证上游连接关闭及下一调用独立。测试客户端仅增加临时证书信任，不修改系统信任或关闭 TLS 校验 |
| 插件连接建立阶段取消 | `plugin::worker::network::tests::cancelling_plugin_network_closes_a_connection_waiting_for_tls` | 复用既有 TLS 等待取消用例，与上述响应体读取阶段分别覆盖 |
| 鉴权重试 | `plugin::registry::tests::worker_auth_retry_uses_persisted_credentials_and_never_replays_partial_output` | 真实 Deno worker 首次拒绝凭据、持久化刷新、重试成功；已经输出后不重试；各次调用记录独立 |
| 重试记录详情和并发凭据刷新 | 既有 `plugin::worker::network::tests`、`plugin::registry::tests` | 复用详细/普通日志、并发刷新及取消后凭据落盘回归 |
| 设置刷新、默认模型、上下文交互 | `apps/desktop/tests/ui/settings.spec.mjs` | 生产前端与真实 Rust 管理服务；实际点击、保存、重新加载后核对界面及持久化数据 |
| 功能失败隔离 | `apps/desktop/tests/state.test.mjs` | 复用已有状态测试，页面测试只补交互接线与真实服务闭环 |
| 子任务、搜索、Steer、新对话入口 | `server/native-agent/*.test.mjs` | 接入模块与合成私有边界的契约；不等于真实 Cursor 执行器验收 |

网关测试只设置隔离数据库中的接管状态，以测试鉴权和模型路由，不执行系统接管。页面测试只对初始目录 GET 注入 503；恢复后的读取、保存及持久化均使用真实服务。插件重试使用本地测试插件返回认证错误，不代表真实服务商授权测试。

## 运行

现有 Rust、Node、Deno、状态及构建检查见[维护指南](../MAINTAINING.md#检查)。插件 worker 用例沿用 `DENO_TEST_EXECUTABLE` 和 `--include-ignored` 专项步骤；未执行该步骤不能计为通过。

页面测试在仓库根目录准备前端与服务：

```sh
npm --prefix apps/desktop ci
npm --prefix apps/desktop run check
cargo build --locked --package cursor-server --bin cursor-server
```

再进入 `apps/desktop`：

```sh
npx playwright install chromium
npm run test:ui
```

测试读取仓库 `target/debug/cursor-server`（Windows 为 `.exe`）；设置 `CARGO_TARGET_DIR` 时使用其绝对路径。每个页面用例启动独立服务、临时数据目录和随机端口，页面与 API 同源；结束后关闭进程并删除临时数据。

[CI](../.github/workflows/ci.yml) 的 Linux Rust 与 Frontend job 独立执行，各自产出服务和生产前端。Management UI job 依赖这两个产物执行 Chromium 测试，不阻塞独立的类型、构建和 Node 检查。失败时上传 `target/ui-tests/` 中的报告、截图、trace 和服务日志。用例不自动重试；时序测试等待事件并设置超时。

## 剩余验收边界

先按本次修改的行为选择验证方式。下面的 E 编号是能力索引，每行可只选择受影响的子项，不是整组必跑清单。

| 类别 | 选择方式 |
| --- | --- |
| CI 已覆盖 | 运行所属自动化用例。仅修改已覆盖的配置规则、协议转换或取消收尾，不因此重新验收原生菜单、登录和工具执行 |
| 可自动化但尚未补齐 | 如新的页面交互、插件断流或超时场景，优先扩展对应测试。只有相关变更当次无法自动验证时，记录临时端到端证据及剩余缺口，不将其固化为每次人工任务 |
| 依赖真实环境 | 修改了 Cursor 私有入口、桌面系统能力或真实服务契约，或收到夹具不能解释的环境故障反馈时，选取下表对应子项，由人工或 agent 验收 |

目前的主要限制：

- Node 原生接入测试使用合成的私有边界，未启动真实 Cursor。网关测试设置隔离数据库中的接管状态，不验证实际安装、模型菜单和 Host 的动作投递。
- 页面测试使用 Chromium 和独立 Rust 服务，仅覆盖设置页目录恢复、默认模型及上下文保存。它不是 Tauri WebView、桌面宿主或整套管理界面的验收。
- 插件取消已覆盖 TLS 等待、响应流读取、接收器关闭及显式取消，但使用测试插件和本地 HTTPS 上游。真实服务商的事件格式、认证、代理兼容性，以及未设置用例的断流/超时场景，需要分别判断。
- CI 的平台编译与插件测试不覆盖对应系统上的证书信任、代理、安装恢复和桌面交互。历史验收记录也不自动证明新构建、新 Cursor/Harness 或新账号组合通过。

### 人工或 agent 的端到端验收清单

“真实客户端＋夹具”指使用实际 BYOK 构建和 Cursor，由本地确定性服务控制模型输出；Cursor 的工具、会话、审批和执行循环仍使用原生实现。“真实服务”指另外使用对应账号和服务商，验证外部兼容性。两类结果分别记录。

| 编号与范围 | 何时补验 | 操作与通过标准 | 所需环境 |
| --- | --- | --- | --- |
| E01 接管与 Harness | 私有入口、安装兼容性或实际运行环境变化 | 在受影响环境开启接管并重启 Cursor，记录实际 Harness，确认请求进入当前 BYOK。固定内置 Harness 的结果只适用于该条件，不代表默认热更新环境通过；不要求为无关变更重复两种环境 | 真实客户端＋夹具 |
| E02 菜单、模型选择与默认值 | 原生目录编码、选项绑定或对话创建入口变化 | 菜单变化验证选项与实际连接；默认初始化变化验证新建、恢复和显式选择；官方模型隔离或失效默认值的处理变化才补相应分支。仅改服务端已覆盖的参数规则不触发整项 | 真实客户端＋夹具；官方实际调用另用真实服务 |
| E03 上下文、思考强度与摘要 | 原生预算/档位接入、元数据刷新或摘要相关行为变化 | 容量接入变化验证同会话调整及下一轮预算；档位变化核对菜单选择和上游参数；只有摘要或历史行为受影响时才跑长任务。单纯参数映射优先用 CI | 真实客户端＋夹具；上游接受性有疑问时用真实服务 |
| E04 文件、终端、审批与 MCP | Host 绑定或原生工具交互受影响 | 选实际受影响的工具完成结果闭环。读写工具核对文件，终端/审批核对批准与拒绝的副作用；仅当 MCP、Todo 或编辑审阅绑定变化时补对应交互，不联动要求全部重验 | 真实客户端＋夹具及所需本地工具 |
| E05 Subagent | 原生 Task 模型选择、父子会话接入变化或子任务故障反馈 | 由父任务发起子任务，读取独立文件中的随机标记并回传；核对实际连接及父子身份。并行或父子取消接入受影响时才补对应场景；仅改已覆盖的通用协议转换不触发整项 | 真实客户端＋夹具 |
| E06 WebSearch 与 WebFetch | 原生搜索入口、展示契约或外部搜索兼容性变化 | 引用展示变化只检查受影响的答案与来源卡片；后端选择变化才验证官方/备用分支；WebFetch、审批或隐私规则变化各自补验。真实搜索仅验证受影响的后端，不因引用拼接修改重跑授权与所有服务商 | 展示用真实客户端＋夹具；外部兼容性用对应真实服务 |
| E07 Stop 与再次发送 | 原生停止信号绑定变化，或出现 CI 未解释的停止故障 | 在受影响的阶段/通道点击 Stop，观察取消结果，再发消息确认旧输出与取消状态不混入。普通网关、worker 和网络收尾使用现有 CI；不自动联动所有工具及账号。已完成的文件修改不要求回滚 | 真实客户端＋夹具；按故障选择直接 API 或插件 |
| E08 Steer、Queue 与 Interrupt | 原生动作投递或步骤消费受影响 | 选所改动作验收：Steer 在下一步骤消费一次且保持同一运行；Queue 等待后续运行；Interrupt 取消后创建新运行。只有共享接收器变更影响多个动作时才一起验证，不因某个按钮调整重跑所有模式 | 真实客户端＋夹具 |
| E09 历史、恢复与会话隔离 | 原生会话/检查点接入、换模恢复变化或真实历史异常 | 恢复变化验证工具往返后重开继续；隔离变化验证两个会话不串结果或停止动作；前缀问题区分普通追加、原生摘要及换模。通用消息投影以 CI 为主，不默认要求重建整段真实对话 | 真实客户端＋夹具 |
| E10 真实模型与账号 | 授权/外部接口契约变化，或真实响应无法由现有夹具解释 | 授权变化才重新登录或控制凭据过期；目录变化验证同步；生成变化验证一次对应请求，工具协议受影响才加工具往返。已覆盖的本地解析修改不默认要求重新授权、消耗额度或重跑全部账号 | 受影响的真实服务；仅原生集成受影响时加 Cursor |
| E11 真实插件/代理兼容性 | 特定服务商流格式、代理/TLS 环境变化或环境故障反馈 | 复现对应服务或代理的问题，核对实际结果与连接生命周期。通用流读取与取消优先使用本地 HTTPS 自动化；新的确定性断流/超时场景优先补 CI，不作为常规人工验收项 | 对应真实插件或代理环境 |
| E12 桌面、安装与恢复 | 系统集成或桌面生命周期受影响 | 证书、代理、窗口关闭、退出/重开、安装恢复和更新分别按实际修改选子项。安装恢复核对文件与设置；Cursor 更新场景确认不覆盖新版本。仅改已覆盖的服务逻辑不要求全套系统操作 | 受影响 OS 的隔离安装与用户目录 |
| E13 管理界面的其余交互 | 未被现有三项页面用例覆盖的界面变更 | 对受影响的新增/编辑/复制/删除模型、账号操作、调用详情、筛选、清理或主题/语言执行真实操作，核对持久化、错误恢复和可用性。浏览器可稳定验证的部分优先新增 UI 用例；WebView、托盘及系统窗口差异使用桌面构建 | 浏览器或实际桌面，按所改能力选择 |
| E14 Commit、TAB 与图像 | 对应原生入口或外部辅助接口契约变化 | 只验所改功能：Commit 核对暂存差异与生成文本；TAB 核对受影响路由；图像核对输入/生成与文件结果及不支持提示。三种能力不互相触发验收 | 真实客户端＋对应夹具或真实服务 |

E05/E06 对应 [Issue #8](https://github.com/Quiyyy/cursor-byok/issues/8)，其中搜索来源的可见性必须从 Cursor 界面检查；E07/E08 对应 [Issue #11](https://github.com/Quiyyy/cursor-byok/issues/11)，按钮停止、连接关闭与步骤引导分别取证。不能仅用工具调用开始、返回 agent ID、网关 HTTP 200 或最终一段回答判定这些项目通过。

Remote SSH、云端工作区、后台 Agent、在途子任务跨进程恢复，以及未列出的平台、模式或 MCP 组合，不从本地用例推导支持或通过。若任务要求支持这些场景，先明确预期行为和环境，再建立专项用例；不把全部探索项默认加入每个 PR 的验收要求。

### 执行、证据与复用

1. 只记录本次受影响的子能力、采用的自动化/真实环境证据，以及仍未验证的受影响部分。无关项无需逐项解释或追溯历史凭证；只有用既有记录替代本次所需验收时，才说明其适用条件。
2. 使用独立安装、BYOK 数据目录、Cursor 用户目录及测试仓库。记录 BYOK 提交/构建、OS、Cursor 版本、实际 Harness 路径/版本和模型通道；临时固定 Harness、修改配置或限制网络必须作为验收条件记录，并在结束后还原。
3. 从对应用户入口操作，关联界面结果、脱敏请求/取消时序、真实文件或工具结果及必要的会话身份。协议夹具不替换原生执行器；真实模型是否遵循指令与指令是否被正确送达分别判断。
4. 每项标为通过、失败、阻塞、未验收或不适用，并附证据位置和原因。缺账号、额度、平台或运行入口时不能计为通过；原生行为不明确时先核对同版本基线，避免把推测写成缺陷。
5. 关闭测试进程并核验安装、代理和临时配置已恢复。证据仅保留脱敏摘要；不提交凭据、完整用户数据库、Cursor 安装备份或私有会话内容。
