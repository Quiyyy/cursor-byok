# 使用指南

[返回项目首页](../README-CN.md) · [下载安装](https://github.com/Quiyyy/cursor-byok/releases) · [提交问题](https://github.com/Quiyyy/cursor-byok/issues)

本指南对应当前源码。发布包的界面与功能以该版本的 Release 说明为准。

## 安装与更新

在 Releases 中选择平台对应资产：

| 平台 | 常用安装资产 |
| --- | --- |
| Windows x64 | NSIS `setup.exe`；便携包见该版本的 Windows ZIP 资产 |
| macOS Apple Silicon | `aarch64.app.tar.gz` 应用压缩包 |
| macOS Intel | `x64.app.tar.gz` 应用压缩包 |
| Linux x64 | AppImage、deb 或 rpm，以实际 Release 资产为准 |

macOS 解压对应架构的应用压缩包，将其中的 `.app` 移入“应用程序”目录后启动。

安装后从应用启动。应用内更新使用本仓库的 Release 资产；不同分发渠道的安装应先手动切换一次。需要从源码运行时参阅[维护说明](../MAINTAINING.md)。

当前源码通过本机 Cursor 的原生 Agent 运行时接入模型。开启接管会备份并安装原生入口，关闭时还原；初次启用后需重启对应 Cursor。模型菜单处于 Auto 时先关闭 Auto，再选择 BYOK 模型。修改模型地址或从旧接管架构切换后，应重新选择当前目录中的模型。已发布包的行为以其版本说明为准。

## 添加 API 模型

打开 **模型管理 → 添加模型**：

| 字段 | 填写方式 |
| --- | --- |
| 类型与请求协议 | 按服务商接口选择 OpenAI Responses、Chat Completions 或 Anthropic Messages |
| 服务器地址 | 服务商基础地址或完整请求 URL，按实际服务的要求填写 |
| API Key | 对应服务商提供的访问密钥 |
| 模型名称 | 服务商接受的模型 ID，可手动输入或通过“获取模型”读取 |
| 显示名称 | 可选；留空使用模型名称 |
| 高级参数 | 备注、上下文容量、输出限制、思考参数、自定义 Headers 与额外 JSON 参数 |

保存后运行 **测试**。协议应根据接口能力选择，不应仅根据模型名称判断。测试结果可查看延迟、生成速度和响应详情。

每个模型右侧的铅笔按钮打开 **模型设置**，API 模型和账号模型使用同一个上下文配置入口。API 的连接地址、密钥与协议仍可点击模型名称或 **⋯ → 编辑连接** 修改；复制操作先创建草稿，保存后才新增模型。右上角 **⋯** 可切换分组、进入平铺排序或导入旧版配置。

## 连接账号

1. 打开 **账号连接**；首次使用按应用提示准备运行组件。
2. 选择对应服务并开始登录，在服务商网页完成授权。
3. 在 **模型目录** 中同步、勾选需要的模型，点击 **保存模型选择**。
4. 返回模型管理进行测试。

账号与模型目录可在同一个弹窗中切换。模型选择在保存前只是草稿。账号冷却或失效时可筛选定位，按服务商提示刷新或重新登录。移除账号会先在行内确认。

## 开启和关闭接管

左上角 **Cursor 接管** 开关在各页面均可使用。

- **首次开启**：若本地证书尚未准备好，应用会打开准备流程。按提示完成初始化和系统信任，刷新状态后再次开启开关。
- **使用时**：保持 Cursor BYOK 运行。首次配置、Cursor 升级或模型列表未更新时，完全退出并重新打开 Cursor，再新建对话。
- **默认模型**：在 **系统设置 → Cursor 默认模型** 中选择已启用的 API 或账号模型，保存后重载 Cursor 窗口。原生默认设置更新后，新对话沿用所选模型；关闭服务端自动切回 Auto 的提示，已有对话保留各自选择。
- **会话选择**：仍可在 Cursor 对话中手动切换模型。主动选择 Auto 时使用 Cursor 官方模型选择逻辑。
- **关闭**：点击开关直接执行，不弹二次确认。处理期间开关不可重复操作，成功后更新状态；请求失败时保留原状态并显示错误。

配置、保存和连通性测试可以在未接管时完成。

默认模型被删除、停用或账号不可用时，需要在 BYOK 中重新选择。应用不会将失效的默认模型悄悄替换为 Auto。未配置默认模型时，仍由 Cursor 管理默认选择。

上下文窗口统一在 **模型管理 → 模型设置** 中选择，支持 **128k、200k、256k、500k、1m、自定义**与 **跟随模型默认**，API 模型和账号模型均可配置。容量按十进制 Token 数保存，例如 `500k = 500000`；请按服务商实际支持的容量选择。

保存后从下一轮对话生效，不需要重建会话；进行中的运行继续使用启动时的配置。账号模型的配置独立于同步目录，刷新模型列表不会覆盖它。选择“跟随模型默认”会清除本地覆盖，旧会话中的历史上下文选项也不会继续覆盖 BYOK 设置。

## 用量与调用记录

运行概览显示调用数、Token 用量、缓存命中率和估算价值。指标详情通过信息提示查看；估算价值按照配置单价计算，不是服务商账单。

柱状图跟随选定时间范围，年度活动默认展开并按 UTC 日分桶。排查错误时打开 **调用记录**，结合模型、协议和服务商响应定位。

## TAB 与提交信息

TAB 补全使用 **系统设置 → TAB 设置** 中的独立连接方式，不由模型管理中的聊天模型自动接管。

提供两种模式：

- **官方直连（默认）**：请求发往 Cursor 官方服务，使用情况取决于 Cursor 账号权限。
- **自定义**：填写兼容 Cursor TAB 接口的服务基础地址，原接口路径会追加到该地址。普通模型 API 地址不能直接作为 TAB 服务使用。

公共服务入口已移除。升级时，已保存的公共服务模式改为官方直连，已有自定义服务地址保留；不会影响模型管理中的聊天模型配置。

提交信息可配置本地模型；未选择本地模型时，现有实现沿用 TAB 的路由配置。

## 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 模型测试失败 | 地址、协议、API Key、模型 ID、代理设置，然后查看错误响应 |
| 测试通过但 Cursor 看不到模型 | 接管状态、是否彻底重启 Cursor、是否新建对话、是否手动选模型 |
| 账号授权过期 | 先刷新账号；服务商已撤销授权时重新登录 |
| 修改模型目录后未生效 | 检查是否点击“保存模型选择” |
| TAB 不可用但聊天正常 | 官方直连检查 Cursor 登录状态与账号权限；自定义模式检查服务地址和对应 TAB 接口 |
| 关闭接管失败 | 查看错误提示与日志；开关不会把失败请求显示为成功关闭 |

默认数据目录为用户目录下的 `.cursor-byok-v3`。记录清理使用应用中的存储管理；排障报告不要附带完整数据库、账号文件或 API Key。反馈入口统一为本仓库 Issues。
